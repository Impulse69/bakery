Redesigning Production Carry-Over

If we keep carry-over amounts read-only, how should we decide which data to pull from?

A

The "Specific Source" Approach

Before the planning grid appears, you see a summary of the "Latest Shortage" with its date and total units.

  • The Choice: You click either "Start Fresh (Ignore Backlog)" or "Carry from [Date]".
  • Clarity: You know exactly which day's failure you are inheriting.
  • Constraint: The amounts remain read-only; you just choose the source day or none.
B

The "Reset on Gap" Approach

System automatically clears carry-overs if the last production run was more than 24 hours ago.

  • Logic: If you skip a day of baking, the system assumes the debt is void.
  • Simple: No buttons to click. It always starts fresh unless you baked "yesterday".
  • Manual Override: A small link to "Restore shortage from [Date]" if you actually want it.
C

The "History Sidebar" Approach

Start fresh by default (0 carry-over). Provide a sidebar listing recent "Missed Targets".

  • Pull vs Push: You don't "inherit" debt; you "import" it.
  • Action: Click "Import shortages from Mar 14" to populate the read-only carry-over fields for today.
